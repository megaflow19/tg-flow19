# TG Flow19 1.0.2

Restores connections on networks that started blocking the Cloudflare proxy domains by name.

## What changed

- **TLS for Cloudflare is now Auto / On / Off** (Settings → TLS for Cloudflare). Auto is the default:
  1. plain TLS on port 443 (HTTP/2 media available);
  2. if the network drops the TLS handshake for the proxy domain on several addresses, TLS with the
     ClientHello split into two TLS records and two TCP segments in the middle of the server name;
  3. if the split connection opens but its data then freezes, port 80 without TLS.

  The working step is remembered for each network; plain TLS is rechecked every hour. **On** uses
  TLS on port 443 only (plain or split), **Off** always uses port 80.
- Settings migrate: if TLS for Cloudflare was on, it becomes **Auto**; if it was off, it stays **Off**.
  If you switched it off because of the blocking, switch it to **Auto**.
- A handshake dropped by name no longer puts Cloudflare addresses on cooldown, and the app stops
  retrying all alternate addresses in a loop when every one of them is blocked by name.
- An alternate address that drops the handshake while another address works is skipped for a while.
- Diagnostics show which transport each Cloudflare connection used (`transport=TLS|TLS_SPLIT|PLAIN`)
  and why it changed (`cf_transport_changed`, `cf_stream_stalled`).

Telegram traffic stays end-to-end encrypted by MTProto on every step; port 80 only drops the outer TLS
layer, so the proxy domain name is visible on that network.

## Updating

- **Obtainium:** updates as usual from `https://github.com/megaflow19/tg-flow19`.
- **Manually:** download `tg-flow19-1.0.2.apk` below and install it over 1.0.1; settings are kept.

Requires **Android 8.0 or newer**. One universal APK (arm64-v8a, armeabi-v7a, x86, x86_64).
